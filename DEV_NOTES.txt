1. Елена, офисный работник, хочет посмотреть новый фильм в выходной день. Ранее ей было сложно выбрать подходящее время и фильм, так как нужно было мониторить расписание и наличие фильма в прокате. Новое приложение упрощает этот процесс, позволяя ей выбрать удобное время для просмотра, ознакомиться с описанием фильма, рейтингами и отзывами других зрителей.

2. Виктор, администратор видеопроката, хочет проверить список заказов и предстоящих сеансов перед началом рабочего дня. Ранее он полагался на бумажные списки или мессенджеры, которые могли быть неактуальными. Новая система предоставляет ему актуальный список заказов и сеансов в реальном времени, что позволяет лучше планировать работу и предоставлять качественный сервис.

3. Мария, помощник менеджера по контенту, готовит каталог фильмов на следующую неделю. Ранее она вручную координировала наличие фильмов в прокате и дублировала каталоги в различных чатах и объявлениях. С новой системой она может видеть актуальное состояние каталога, планировать добавление новинок и убирать фильмы, которые перестали быть востребованными.

Описание и реализация RESTful API

RESTful API реализован для асинхронного взаимодействия клиентской части веб-приложения с сервером. API работает по принципу клиент-серверной архитектуры, где клиент отправляет HTTP запросы, а сервер возвращает ответы в формате JSON. Авторизация пользователей выполняется через сессии, которые передаются с каждым запросом автоматически через cookies. Для индикации результата выполнения операций используются стандартные HTTP статусы: 200 OK для успешных операций, 401 Unauthorized для неавторизованных пользователей, 403 Forbidden для запрещенных действий, 400 Bad Request для ошибок валидации данных.

Маршрутизация API запросов выполняется на основе HTTP метода и параметров в теле запроса. Для проекта управления фильмами реализованы следующие API endpoints для ресурса "История и действия пользователей":

POST /api/history.php с action=status - возвращает статус авторизации и список купленных фильмов пользователя. Доступно только для авторизованных пользователей. Запрос не требует дополнительных параметров в теле. Сервер проверяет наличие сессии пользователя и возвращает JSON с полем purchasedFilmIds, содержащим массив ID купленных фильмов. При отсутствии авторизации возвращается статус 401.

POST /api/history.php с action=checkout - выполняет покупку фильмов из корзины. В теле запроса передается JSON объект с полем items, содержащим массив информации о фильмах (filmId, title, price). Сервер проверяет валидность данных, подтверждает оплату, сохраняет информацию о покупке в базе данных MySQL и возвращает обновленный список купленных фильмов. При успешной операции возвращается статус 200 и JSON с массивом purchasedFilmIds. Если пользователь не авторизован, возвращается статус 401. Если в корзине нет новых фильмов для покупки, возвращается ошибка с сообщением о невозможности оплаты.

POST /api/history.php с action=view - регистрирует просмотр фильма пользователем. В теле запроса передаются filmId и title фильма. Сервер проверяет авторизацию пользователя и наличие фильма в списке купленных. Если проверки пройдены успешно, сохраняется информация о просмотре в базе данных с отметкой времени. При успешной операции возвращается статус 200. Если пользователь не купил фильм, возвращается статус 403 с сообщением о необходимости оплаты.

POST /api/track.php с action=rating - сохраняет оценку пользователя для фильма. В теле запроса передаются score (целое число от 1 до 10), filmId и context (контекст оценки, например movie_after_watch). Оценка сохраняется в системе аналитики для дальнейшей обработки и формирования статистики рейтингов фильмов. Запрос использует параметр keepalive для гарантии отправки данных даже при закрытии страницы пользователем. При успешной операции возвращается статус 200.

Права доступа к API endpoints контролируются через проверку сессии пользователя. Авторизованные пользователи имеют доступ ко всем операциям с фильмами, которые они купили. Неавторизованные пользователи получают статус 401 при попытке доступа к защищенным ресурсам. Администратор имеет полный доступ к управлению фильмами через админ-панель, которая использует отдельные механизмы авторизации через cookies с логином admin1. Все API запросы выполняются асинхронно через JavaScript с использованием fetch API и передают credentials: 'same-origin' для корректной работы с сессиями.
