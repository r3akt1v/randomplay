5.1 Создание и описание админ-панели

Админ-панель реализована на основе традиционной PHP архитектуры с возможностью управления кастомными фильмами. Основной принцип работы: сервер-сайд генерация HTML интерфейса с обработкой форм через POST запросы. Для интерактивных операций редактирования реализовано модальное окно с JavaScript.

Создана страница admin.php с формой авторизации для администратора. Доступ к панели ограничен через проверку cookies с логином admin1. При успешной авторизации администратор получает доступ к функциям управления каталогом фильмов. Страница включает таблицу с отображением текущих кастомных фильмов и формы для добавления новых фильмов.

Реализована загрузка списка кастомных фильмов из JSON файла через функцию custom_films_load_raw(). Полученный массив данных преобразуется в HTML таблицу с колонками: Title, ID, Price, Action. Для каждого фильма отображаются название, уникальный идентификатор, цена и кнопки управления. Валидация ID фильмов выполняется через регулярное выражение для обеспечения безопасности.

Разработана система CRUD операций для управления фильмами. Операция добавления реализована через форму с полями Title, Price, Genre, Description. При отправке формы данные обрабатываются функцией custom_films_append(), которая генерирует уникальный ID фильма и сохраняет данные в JSON файл. Операция удаления выполняется через кнопку Delete с подтверждением через JavaScript. Функция custom_films_remove() удаляет фильм из массива данных по ID и сохраняет обновленный список.

Для операции редактирования реализовано модальное окно с формой, дублирующей структуру формы добавления. При нажатии кнопки Edit открывается модальное окно с текущими данными фильма, которые загружаются через JavaScript функцию openEditModal(). Пользователь может изменить название, цену, жанр и описание фильма. При сохранении форма отправляет POST запрос с action=update_film, который обрабатывается функцией custom_films_update(). Функция находит фильм по ID в массиве данных, обновляет поля и сохраняет изменения в JSON файл.

Технические особенности реализации: сервер-сайд валидация всех входных данных (максимальная длина названия 200 символов, ограничение цены от 0 до 9999999 руб, ограничение длины описания 12000 символов), проверка корректности жанра (action, drama, comedy, fantasy), защита от CSRF через проверку сессий администратора, автоматическая генерация уникальных ID фильмов, обработка ошибок с отображением сообщений пользователю, адаптивный дизайн интерфейса с использованием CSS стилей.

5.2 Описание и реализация RESTfull API

REST API реализован для асинхронного взаимодействия клиентской части с сервером. API работает по принципу клиент-серверной архитектуры, где клиент отправляет HTTP запросы, а сервер возвращает ответы в формате JSON. Авторизация пользователей выполняется через сессии, которые передаются с каждым запросом автоматически через cookies. Для индикации результата выполнения операций используются стандартные HTTP статусы: 200 OK для успешных операций, 401 Unauthorized для неавторизованных пользователей, 403 Forbidden для запрещенных действий, 400 Bad Request для ошибок валидации данных.

Маршрутизация API запросов выполняется на основе HTTP метода и пути запроса. Путь запроса сегментируется на ресурс и идентификатор объекта. Для проекта управления фильмами реализованы следующие API endpoints для ресурса "История и действия пользователей":

POST /api/history.php с action=status - возвращает статус авторизации и список купленных фильмов пользователя. Доступно только для авторизованных пользователей. Возвращает JSON с полем purchasedFilmIds, содержащим массив ID купленных фильмов.

POST /api/history.php с action=checkout - выполняет покупку фильмов из корзины. В теле запроса передается массив items с информацией о фильмах (filmId, title, price). Сервер проверяет оплату, сохраняет информацию о покупке в базе данных и возвращает обновленный список купленных фильмов. При успешной операции возвращает статус 200 и список купленных фильмов.

POST /api/history.php с action=view - регистрирует просмотр фильма пользователем. Передается filmId и title фильма. Проверяется, что пользователь купил фильм, затем сохраняется информация о просмотре. Возвращает статус 200 при успешной операции.

POST /api/track.php с action=rating - сохраняет оценку пользователя для фильма. Передается score (1-10), filmId и context. Оценка сохраняется в системе аналитики для дальнейшей обработки. Использует keepalive для гарантии отправки данных даже при закрытии страницы.

Права доступа к API endpoints контролируются через проверку сессии пользователя. Авторизованные пользователи имеют доступ ко всем операциям с фильмами, которые они купили. Неавторизованные пользователи получают статус 401 при попытке доступа к защищенным ресурсам. Администратор имеет полный доступ к управлению фильмами через админ-панель, которая использует отдельные механизмы авторизации.

Для демонстрации работы API необходимо сфотографировать: экран с результатом GET запроса к /api/history.php (статус пользователя и список купленных фильмов), экран с отправкой POST запроса для оформления заказа через корзину, экран с успешным ответом после покупки фильма, экран с модальным окном оценки фильма после просмотра.
